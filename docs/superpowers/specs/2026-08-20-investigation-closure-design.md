# 实验资产中心排查闭环与生产可信度设计

## 目标

在保留当前 Arco/Semi 风格与实验生命周期导航的前提下，把分散的监控告警、实验详情、父子关系、Seed 使用、放量变化和校验结果组织成一条可操作、可追溯的排查链路。同时解决当前审计发现的无障碍、移动端定位、状态对比度和验证脚本假安全感问题。

本轮完成后，普通用户应能从一个异常或实验出发，在不重复选择对象的情况下回答：发生了什么、涉及哪些实验和平台、近期有哪些变更、哪些校验支持当前判断、谁负责处理、处理到了哪一步。

## 方案选择

采用“排查闭环优先”方案。

- 不新增一级导航，避免继续扩大左侧功能树。
- 使用共享排查上下文贯穿监控排查、父子实验、放量历史、实验校验和详情抽屉。
- 页面保留各自专业视图，但都能读取和更新同一个排查对象、时间范围和证据焦点。
- 无障碍、响应式和验证体系与功能改造同轮完成，避免在新交互上继续累积问题。

未采用的方案：

- 技术债优先：工程更稳，但不能尽快验证平台最关键的排查价值。
- 各模块独立增强：单页效果提升快，但用户仍需跨页面重复定位和拼接证据。

## 范围

### 本轮包含

1. 共享排查上下文与处理状态流。
2. 运行中监控排查的证据链和处置动作。
3. 父子实验的关系链路、影响方向、关系风险和变更记录。
4. 放量历史的聚焦模式、事件时间线、异常筛选和原因完整性。
5. 实验详情中的统一证据时间线和排查入口。
6. 抽屉语义、焦点管理、表单可访问名称、颜色对比度和 reduced motion。
7. 移动端当前导航自动定位、触控目标和复杂视图降级。
8. 独立的源码、静态 HTML 和真实浏览器验证。

### 本轮不包含

- 真实后端、登录系统、数据库和生产权限服务。
- 真实统计引擎或 SQL 执行。
- 自动修改业务平台实验状态。
- 通用图数据库或任意规模关系图引擎。
- 把静态 HTML 改造成必须依赖开发服务器才能运行的构建产物。

## 核心数据模型

### InvestigationContext

共享排查上下文，包含：

- `caseId`：本地排查编号。
- `experimentId`：当前主实验。
- `alertId`：可选的触发告警。
- `timeRange`：7 天、14 天、30 天或自定义范围。
- `entrySource`：监控、清单、关系、放量或校验。
- `evidenceFocus`：关系、放量、Seed、校验、指标异常之一。
- `status`：未开始、排查中、待协同、已定位、已关闭。
- `owner`、`collaborators`、`resolution`、`updatedAt`。

上下文写入 `sessionStorage`，并在 URL hash 中保留可分享的最小参数，例如：

```text
#investigate?experiment=EXP-240611-017&alert=ALT-003&range=14d
```

刷新、浏览器前进后退和跨页面跳转后仍能恢复当前排查对象。非法参数回退到安全页面并修正 URL，不保留页面与地址不一致的状态。

### EvidenceEvent

统一证据事件，包含：

- 时间、实验、事件类型、来源平台、操作人。
- 变更前后值或校验结论。
- 关联父子/互斥实验。
- 原因、数据质量状态、证据链接。
- 风险级别和是否需要处理。

放量、Seed 使用、关系变更、校验、指标告警都转换为该结构，按时间倒序形成统一证据时间线。

### ResolutionAction

处理动作采用有限状态流：

```text
未开始 -> 排查中 -> 待协同 -> 已定位 -> 已关闭
                    \-> 排查中
```

每次状态变化记录操作人、时间、备注和下一步。静态 demo 使用本地状态和 toast 呈现，不伪装成已提交后端。

## 页面设计

### 运行中监控排查

- 顶部保留异常概览，但不再使用四个同构大指标卡占据首屏。
- 主区域使用“异常队列 + 当前排查”布局。
- 点击异常的“开始排查”后生成排查上下文，页面展示对象、严重度、负责人、时间范围和处理状态。
- 证据链按时间组织，并提供“查看关系”“查看放量”“重新校验”动作；动作切页时保留上下文。
- 问题类型是实际筛选器，使用标准 checkbox 或 segmented control，并展示命中数量。

### 父子实验

- 关系视图改为三段式链路：上游/父实验、当前实验、下游/子实验与互斥实验。
- 节点展示实验名称、状态、当前放量、平台和质量风险；连线旁显示关系类型和影响范围。
- 复杂关系仍通过下方表格完整承载，关系图只负责快速理解，不替代表格。
- 风险队列中的记录可以聚焦当前关系并进入排查上下文。
- 增加关系变更记录，说明谁在何时建立、修改或解除关系。

### 放量历史

- 全局模式支持实验、动作、操作人、来源平台、原因完整性和时间范围筛选。
- 聚焦模式显示当前实验和排查上下文，并提供“返回全部放量”。
- 首屏先展示关键时间线和异常事件，再展示完整表格，避免筛选器和空白面板挤压主体。
- 无原因、短时间多次放量、补录覆盖历史等异常可直接加入当前排查。

### 实验详情

- 保留详情抽屉，新增“开始/继续排查”和统一证据时间线。
- 关系、放量、校验、来源质量和复盘摘要均可跳到对应聚焦页面。
- 抽屉使用标准 dialog 语义；打开时聚焦标题或关闭按钮，Tab 不进入背景，关闭后恢复触发按钮焦点。

## 可访问性与响应式

- 所有抽屉增加 `role="dialog"`、`aria-modal="true"`、`aria-labelledby` 和焦点恢复。
- 背景区域在抽屉打开时设置 `inert`；Escape 关闭最上层浮层。
- 输入框和表格内选择器补充显式 label 或 `aria-label`。
- 调整 `--text-3` 及成功、警告、危险文字色，正文和小字号达到 WCAG AA。
- 增加 `prefers-reduced-motion: reduce` 分支。
- 移动端导航加载或 hash 变化后自动把当前项滚动到可见位置。
- 移动端操作按钮和导航目标至少 44px；表格操作链接使用更大的点击区域。
- 父子关系在窄屏降级为上下游分组列表，放量事件降级为时间线，不要求用户横向阅读宽表。

## 工程边界

- 保持 `src/App.tsx`、`src/styles.css` 和 `dist/index.html` 同步。
- 将新增的排查数据、纯函数和 hash 解析集中到独立模块，减少继续膨胀 `App.tsx`。
- 静态 HTML 保留等价逻辑；共享约束通过验证脚本检查，而不是依赖人工记忆。
- `verify-ui.mjs` 分别验证 React 源码和静态 HTML，不再把多个文件拼接后统一 `includes`。
- 新增真实浏览器 smoke 验证，覆盖导航、上下文恢复、焦点、Esc、非法 hash、移动导航和三档视口溢出。

## 错误与边界处理

- 找不到实验、告警或关系时展示明确空状态，并提供返回实验清单。
- 无证据事件时说明当前时间范围无记录，而不是保留空白面板。
- 非法 hash 自动清理并回退到实验评估。
- 当前角色无权访问管理员页面时回退普通用户页，不保留受限 URL。
- sessionStorage 不可用时退化为当前会话内存状态，不阻断操作。
- 本地处理动作明确标注“演示状态”，避免被误认为已写入生产系统。

## 验收标准

1. 从任一监控告警开始排查后，关系页、放量页、校验页和详情均自动聚焦同一实验。
2. 刷新页面或浏览器前进后退后，排查上下文与 URL 保持一致。
3. 父子实验关系视图不再为空，能说明方向、关系类型、平台、放量和风险。
4. 放量历史首屏能看到当前实验时间线，并能查询全部记录和异常记录。
5. 异常记录可以进入有限状态处理流，且每次动作都有可见反馈。
6. 抽屉键盘焦点不进入背景，关闭后返回触发元素。
7. 可见表单控件有可访问名称，小字号文本及状态色满足 AA。
8. 390、585、1366 宽度无页面级横向溢出；移动端当前导航可见。
9. 源码检查、静态 HTML 检查、inline script 语法和真实浏览器 smoke 全部通过。
10. 改造前后均保留 history 快照，并更新 README、CHANGELOG 和 history 索引。
